Создай полный UX/UI-дизайн мобильного приложения умного гардероба Shine. Нужны макеты всех основных экранов, состояний и пользовательских сценариев приложения, а также отдельный UI-kit.

Язык интерфейса — русский.
Название бренда — Shine.
Слоган оставить на английском: “Shine bright like a diamond”.

ОБЩАЯ КОНЦЕПЦИЯ

Shine — мобильное приложение умного гардероба. Пользователь добавляет собственную одежду, а приложение с помощью ИИ составляет готовые образы с учётом:
— вещей пользователя;
— погоды;
— ситуации;
— предпочтений и стиля;
— предыдущей реакции пользователя на предложенные образы.

Главная задача продукта — максимально быстро ответить пользователю на вопрос «Что надеть?».

Это НЕ виртуальная примерочная. Не нужно генерировать изображение человека в подобранной одежде. Результат подбора показывается как эстетичный коллаж отдельных вещей.

Пользователь может пользоваться основной функцией без регистрации. Регистрация или вход предлагаются только тогда, когда пользователь хочет сохранить образ или собственный гардероб.

Фотография самого пользователя используется только для персонализации: при первом входе можно необязательно загрузить своё фото и имя, получить короткий комплимент от ИИ, после чего фотография остаётся в профиле и может эстетично использоваться на главной странице. Фото можно пропустить.

--------------------------------------------------
ВИЗУАЛЬНЫЙ СТИЛЬ
--------------------------------------------------

Основное направление:
quiet luxury + contemporary luxury + high-fashion editorial.

Приложение должно выглядеть как современный премиальный fashion-продукт, а не как типичное AI-приложение, маркетплейс или стандартный мобильный сервис.

Ассоциации:
— тихая роскошь;
— высокая мода;
— fashion-журнал;
— премиальная съёмка;
— уверенность;
— спокойствие;
— индивидуальность;
— минимализм;
— дорогая редакционная верстка.

Не используй визуальные клише AI: градиентные фиолетово-синие кнопки, светящиеся элементы, роботов, звёздочки вокруг AI, стеклянные карточки и т. п.

ЦВЕТА

Основная тема — тёмная.

Создай цветовую систему примерно в следующем направлении:
— основной фон: глубокий почти чёрный / угольный #0D0D0D;
— вторичный фон и поверхности: #171717 / #1D1D1D;
— основной светлый текст: тёплый off-white #F3F0E9;
— вторичный текст: приглушённый серый;
— светлый дополнительный фон: ivory / молочный;
— основной акцент: глубокий премиальный бордовый / oxblood, ориентировочно #6B1F2B или близкий по характеру оттенок;
— дополнительные оттенки бордового можно использовать для состояний, небольших заливок и декоративных деталей.

Бордовый должен использоваться дозированно. Не делай интерфейс чёрно-красным. Он должен восприниматься как акцент luxury-fashion бренда.

Не используй золото как основной акцент.

ТИПОГРАФИКА

Используй сочетание двух шрифтов:

1. Элегантная fashion serif-гарнитура для:
— логотипа Shine;
— крупных заголовков;
— эмоциональных сообщений;
— editorial-акцентов;
— отдельных цифр.

2. Современный нейтральный sans-serif / grotesk для:
— основного текста;
— кнопок;
— тегов;
— навигации;
— подписей;
— характеристик вещей;
— форм.

Допускается italic serif для отдельных слов и эмоциональных акцентов.

Типографика должна быть важной частью композиции. Используй сильный контраст размеров: очень крупные editorial-заголовки + маленький функциональный текст.

При этом весь функциональный текст должен оставаться хорошо читаемым на мобильном устройстве.

КОМПОЗИЦИЯ

Используй:
— много свободного пространства;
— editorial-композицию;
— асимметрию там, где она не мешает UX;
— крупные заголовки;
— выразительное кадрирование;
— тонкие разделительные линии;
— сеточную структуру;
— сочетание крупных и маленьких элементов;
— минимальное количество декоративных деталей.

Не делай каждый элемент отдельной карточкой.

НЕ используй большие скругления.
Все основные контейнеры, карточки, фотографии, кнопки и поля должны иметь ПРЯМЫЕ УГЛЫ или минимальный радиус 0–2 px.

Минимум теней. Предпочтительнее разделять элементы цветом поверхности, расстоянием и тонкими линиями.

ФОТОГРАФИИ

НЕ ГЕНЕРИРУЙ изображения людей, одежды, аксессуаров или fashion-фотографии.

Везде, где должна находиться фотография, поставь простой прямоугольный placeholder нейтрального серого цвета.

Подпиши внутри:
— «Фото пользователя»;
— «Фото вещи»;
— «Фото образа»;
— «Fashion image»;
— «Фото из гардероба»
и т. д.

Не добавляй иллюстрации вместо фотографий.

Я самостоятельно заменю эти placeholders на нужные изображения в Figma.

--------------------------------------------------
СОЗДАЙ ВСЕ СЛЕДУЮЩИЕ ЭКРАНЫ И СОСТОЯНИЯ
--------------------------------------------------

1. SPLASH SCREEN

— логотип Shine;
— слоган “Shine bright like a diamond”;
— минималистичная premium-композиция;
— тёмный фон.

2. ПЕРВЫЙ ЭКРАН / ЗНАКОМСТВО

Кратко объяснить идею Shine.
Основное действие — начать пользоваться приложением.
Не заставлять регистрироваться.

3. НЕОБЯЗАТЕЛЬНАЯ ПЕРСОНАЛИЗАЦИЯ

Предложить:
— загрузить своё фото;
— указать имя.

Обязательно показать заметное действие «Пропустить».

Объяснить, что это нужно для персонализации пространства, а не для виртуальной примерки.

4. ЗАГРУЗКА ФОТО ПОЛЬЗОВАТЕЛЯ

— большой прямоугольный placeholder;
— загрузить из галереи;
— сделать фото;
— продолжить;
— пропустить.

5. РЕАКЦИЯ ИИ НА ФОТО

После загрузки показать фото-placeholder пользователя и 2–3 коротких комплимента/позитивных сообщения.

Тон уверенный, ненавязчивый, fashion-oriented. Без чрезмерной милоты и эмодзи.

Например по смыслу:
«У тебя сильная база для выразительных образов»
«Будем собирать образы, которые работают именно на тебя»

После этого CTA «Перейти в Shine».

6. ГЛАВНАЯ — ГОСТЬ

Это один из ключевых экранов.

Должны быть:
— Shine;
— погода;
— крупный editorial-заголовок, связанный с вопросом «Что надеть сегодня?»;
— заметный CTA «Подобрать образ»;
— ситуации;
— небольшой персональный/editorial-блок;
— предложение попробовать сервис без регистрации.

Не перегружай главный экран.

7. ГЛАВНАЯ — АВТОРИЗОВАННЫЙ ПОЛЬЗОВАТЕЛЬ

Добавь:
— имя;
— фото пользователя в виде прямоугольного fashion-placeholder, НЕ круглого аватара;
— погоду;
— «Подобрать образ»;
— ситуации;
— последний сохранённый/недавний образ;
— персональную короткую рекомендацию.

Главная должна выглядеть как персональная fashion-страница пользователя.

8. ВЫБОР СИТУАЦИИ

Пять вариантов:
— Работа
— Учёба
— Свидание
— Спорт
— Повседневный

Сделай выбор визуальным и быстрым.

Не используй пять одинаковых огромных rounded cards.

9. ВЫБОР ИСТОЧНИКА ОДЕЖДЫ

Если у пользователя ещё нет гардероба:

«Из чего соберём первый образ?»

Варианты:
— Добавить свои вещи
— Попробовать на примере

Объяснить, что попробовать Shine можно без регистрации и заполнения всего гардероба.

10. ШАБЛОННЫЙ ГАРДЕРОБ

Покажи несколько placeholder-вещей.

Пользователь может выбрать предложенный набор и сразу перейти к подбору.

11. ГАРДЕРОБ — ЗАПОЛНЕННОЕ СОСТОЯНИЕ

— сетка вещей;
— прямоугольные placeholders;
— категории;
— фильтры;
— кнопка добавления вещи.

Категории могут включать:
— Все
— Верх
— Низ
— Платья
— Верхняя одежда
— Обувь
— Аксессуары

12. ГАРДЕРОБ — ПУСТОЕ СОСТОЯНИЕ

Красивое минималистичное empty state.

Текст по смыслу:
«Здесь пока пусто. Добавь первые вещи — Shine начнёт собирать образы из твоего гардероба».

CTA «Добавить вещь».

13. ДОБАВЛЕНИЕ ВЕЩИ

Bottom sheet или отдельный экран:
— Сделать фото
— Выбрать из галереи

Прямые углы.

14. ЗАГРУЗКА / РАСПОЗНАВАНИЕ ВЕЩИ

Покажи:
— placeholder фотографии;
— состояние анализа;
— минималистичный индикатор загрузки;
— текст «Определяем характеристики вещи».

Не используй футуристические AI-эффекты.

15. РЕЗУЛЬТАТ РАСПОЗНАВАНИЯ

Например:
Фото вещи

Категория: Верх
Тип: Жакет
Цвет: Чёрный
Стиль: Классический
Сезон: Демисезон

Все характеристики определены автоматически.

Пользователь может нажать на тег/поле и изменить значение.

CTA «Добавить в гардероб».

16. ОШИБКА РАСПОЗНАВАНИЯ

Понятное состояние:
«Не удалось хорошо рассмотреть вещь»

Предложить:
— Сделать другое фото
— Выбрать другое из галереи

Не использовать технические сообщения об ошибках.

17. КАРТОЧКА ВЕЩИ

— крупный placeholder;
— характеристики;
— редактирование;
— удалить;
— информация о том, в каких сохранённых образах используется вещь.

18. ПОДГОТОВКА ОБРАЗА

После выбора ситуации показать короткое состояние формирования рекомендации.

Например:
«Собираем образ для учёбы»
«Учитываем +12°, дождь и твои предпочтения»

Минималистичный loading state.

19. РЕЗУЛЬТАТ — ГОТОВЫЙ ОБРАЗ

Это второй ключевой экран после главной.

Покажи образ как editorial-коллаж из нескольких прямоугольных placeholders вещей.

Например:
— верх;
— низ;
— обувь;
— верхняя одежда;
— аксессуар.

Добавь:
— название образа;
— ситуация;
— температура/погода;
— короткое описание;
— «Сохранить»;
— «Другой вариант».

Коллаж должен выглядеть как fashion-editorial layout, а не как обычная сетка интернет-магазина.

20. БЫСТРЫЕ КОРРЕКТИРОВКИ ОБРАЗА

После нажатия на изменение показать готовые команды:

— Другой стиль
— Хочу теплее
— Хочу легче
— Более базовый
— Более выразительный

Не добавляй поле для написания сообщения ИИ.

21. АЛЬТЕРНАТИВНЫЙ ОБРАЗ

Покажи второй вариант коллажа после корректировки.

Должно быть понятно, что рекомендации изменились.

22. ЗАМЕНА ОДНОЙ ВЕЩИ

Позволить нажать на конкретную вещь в образе и выбрать:
«Заменить эту вещь».

Показать 2–4 альтернативных placeholder-варианта из гардероба.

23. СОХРАНЕНИЕ — АВТОРИЗОВАННЫЙ ПОЛЬЗОВАТЕЛЬ

Небольшое premium-состояние успешного сохранения:
«Образ сохранён».

24. СОХРАНЕНИЕ — ГОСТЬ

Если гость нажимает «Сохранить», показать:
«Сохрани образ и свой гардероб»

Предложить:
— Зарегистрироваться
— Войти

Не блокировать предыдущий результат и не создавать ощущение принудительной регистрации.

25. РЕГИСТРАЦИЯ

Минималистичная форма.

Не перегружать полями.

26. ВХОД

Минималистичная форма входа.

27. СОХРАНЁННЫЕ ОБРАЗЫ

Editorial-сетка сохранённых образов.

Каждый образ:
— placeholder коллажа;
— название;
— ситуация;
— дата или короткая подпись.

28. СОХРАНЁННЫЕ ОБРАЗЫ — EMPTY STATE

Сообщение о том, что сохранённых образов пока нет.

CTA «Подобрать первый образ».

29. ДЕТАЛЬНАЯ СТРАНИЦА СОХРАНЁННОГО ОБРАЗА

— коллаж;
— вещи;
— ситуация;
— погода;
— название;
— повторить образ;
— удалить из сохранённых.

30. ПРОФИЛЬ

Используй фотографию пользователя как крупный прямоугольный editorial-element, а не стандартный круглый avatar.

Покажи:
— имя;
— фото;
— предпочтения;
— стиль;
— настройки;
— аккаунт.

31. ПРЕДПОЧТЕНИЯ СТИЛЯ

Пользователь может выбрать несколько направлений стиля.

Не используй фотографии — только placeholders.

32. НАСТРОЙКИ

Минималистичный список:
— Аккаунт
— Персонализация
— Погода / город
— Уведомления
— Конфиденциальность
— Обратная связь
— Выйти

33. СОСТОЯНИЕ «НЕТ ПОДХОДЯЩЕГО ОБРАЗА»

Например:
«Сегодня гардероб немного ограничивает варианты»

Предложить:
— Изменить условия
— Посмотреть ближайший вариант
— Добавить вещи

34. ОШИБКА ЗАГРУЗКИ

Понятное сообщение + повтор действия.

35. НЕТ ИНТЕРНЕТА

Минималистичное состояние без лишних иллюстраций.

36. CONFIRMATION MODAL

Создай универсальный modal для подтверждения удаления вещи/образа.

37. TOAST / SUCCESS / ERROR

Создай системные состояния:
— успех;
— ошибка;
— информация.

UI-KIT И DESIGN SYSTEM
--------------------------------------------------

Создай ОТДЕЛЬНУЮ страницу/секцию «Shine UI Kit».

Вынеси в переиспользуемые стили / variables:

1. COLORS

Создай стили colors

2. TYPOGRAPHY

Создай Text Styles

Раздели serif/display и sans-serif функциональную типографику.

3. SPACING

Создай единую систему отступов и variables для spacing.

Используй последовательную шкалу, например:
4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64.

4. GRID

Настрой единый mobile grid и одинаковые боковые поля.

5. COMPONENTS

Все повторяющиеся элементы сделай компонентами с variants.

6. ICONS

Используй один минималистичный outline icon set.
Одинаковая толщина линий.
Не смешивай разные стили иконок.

7. CORNERS

Основной radius = 0.
Допустимый технический radius для мелких элементов = максимум 2 px.
Не используй pill-shaped кнопки, кроме маленьких функциональных chips, если это действительно необходимо.
