# Стилизация Shine: классы и CSS-переменные

## Что изменено

1. Tailwind удалён из `package.json`, `vite.config.ts` и `src/index.css`.
2. Во всём `src` удалены inline-стили `style={{ ... }}`. Размеры, отступы, цвета и раскладка теперь задаются CSS-классами.
3. В `src/index.css` добавлен класс темы `.shine-theme`. Он содержит дизайн-токены: цвета, шрифты, радиусы и общие параметры интеракций.
4. `.shine-theme` назначается корню приложения как в режиме макета телефона, так и на реальном устройстве. Поэтому все дочерние компоненты получают одинаковые переменные.
5. Повторяемые UI-элементы получили понятные классы: `.btn`, `.caption`, `.tag`, `.image`, `.radio`, `.bottom-nav__item`, `.outfit-piece` и другие.
6. Статическая раскладка экранов вынесена в `src/generated-styles.css`. Этот файл подключается из `src/index.css`; в нём нет JavaScript-стилей, только CSS-классы.

## Как устроены переменные

```css
.shine-theme {
  --color-bg: #0d0d0d;
  --color-text: #f3f0e9;
  --color-accent: #6b1f2b;
  --font-sans: "DM Sans", sans-serif;
  --font-serif: "Playfair Display", serif;
}

.btn--primary {
  background: var(--color-text);
  color: var(--color-bg);
}
```

`.shine-theme` создаёт область видимости переменных. Любой вложенный элемент может использовать `var(--color-bg)`. Если поменять значение токена один раз в теме, цвет изменится во всех компонентах, которые используют этот токен.

Это отличается от класса вида `.red { color: red; }`: такой класс задаёт конкретное свойство конкретному элементу. Класс темы задаёт **значение переменной**, а компоненты сами решают, для какого свойства её использовать.

## Почему классы, а не inline-стили

Inline-подход:

```tsx
<button style={{ padding: 16, color: "#F3F0E9" }}>Сохранить</button>
```

Текущий подход:

```tsx
<button className="btn btn--primary">Сохранить</button>
```

```css
.btn { padding: 15px 24px; }
.btn--primary { color: var(--color-bg); }
```

Плюсы CSS-классов:

- одинаковые правила не дублируются в JSX;
- дизайнерские значения меняются централизованно;
- состояния `:hover`, `:focus-visible`, `:active`, media queries и псевдоэлементы работают естественно;
- разметка описывает структуру и смысл, CSS — внешний вид;
- браузер может переиспользовать CSS-правила эффективнее, чем множество разрозненных inline-объектов.

## Почему это не Tailwind

Tailwind — utility-first библиотека: множество готовых классов вроде `p-4`, `bg-zinc-900`, `flex`. Здесь Tailwind не подключён. Классы написаны внутри проекта и отражают собственную дизайн-систему Shine: `.btn`, `.radio`, `.outfit-piece`, `.shine-theme`.

## Что можно показать преподавателю

1. `src/index.css` — токены темы и переиспользуемые классы компонентов.
2. `src/generated-styles.css` — статические правила раскладки, вынесенные из JSX.
3. `src/components/ui/Btn.tsx` — компонент выбирает модификатор `btn--primary` / `btn--secondary`, а не формирует объект стилей.
4. `src/pages/outfit/SituationScreen.tsx` — состояние выбора меняет CSS-класс `radio--selected`, а не inline-цвета и границы.
5. `vite.config.ts` и `package.json` — Tailwind-плагин и зависимость удалены.

## Возможные вопросы на защите

### Почему переменные объявлены классом, а не в `:root`?

`:root` делает токены глобальными для всего документа. `.shine-theme` ограничивает их конкретным приложением или темой. Можно добавить второй класс, например `.shine-theme--light`, и переопределить только значения переменных, не переписывая компоненты.

### Что такое дизайн-токен?

Это именованное повторяемое дизайнерское решение: цвет фона, акцентный цвет, шрифт, радиус или шаг отступа. Токен хранится один раз, а используется много раз через `var(...)`.

### Что означает модификатор `--primary`?

Это соглашение БЭМ-подобного стиля. Базовый класс `.btn` описывает общую форму кнопки, а `.btn--primary` добавляет вариант внешнего вида. Так не нужно копировать все свойства для каждого варианта.

### Почему не делать один огромный CSS-класс на весь экран?

Один класс сложно переиспользовать и изменять. Компонентные классы позволяют независимо менять кнопку, radio-индикатор, карточку или навигацию, сохраняя единые токены темы.

### Когда inline-стиль всё-таки допустим?

Он полезен для действительно уникального значения, вычисляемого в рантайме: например, позиция мыши в canvas или ширина графика из API. Для постоянных интерфейсных размеров, цветов и состояний предпочтительнее CSS-классы и модификаторы.
